# Chessling 보드 가이드(화살표·칸 표시) 설계 문서

- 작성일: 2026-10-02
- 상태: 설계 확정, 구현 계획 작성 전
- 선행 스펙: `2026-10-01-chessling-commentary-quiz-design.md`. 이 문서는 보드 위 가이드 표시만 추가한다.
- 브랜치: `feat/board-guide`

## 1. 목적과 범위

기보를 넘기거나 리뷰할 때, 코멘트·해설이 말하는 내용을 **보드 위에 화살표와 칸 표시로** 보여 준다.
"이 수가 무엇을 노리는지", "어떤 기물이 위험한지", "무엇을 놓쳤는지"를 글을 다 읽지 않아도 알 수 있게 한다.

| 대상 | 가이드 출처 |
|---|---|
| 내 대국·대회 대국 | 자동 계산. 판 위 사실은 리뷰 없이도, 놓친 수는 리뷰한 뒤에만 그린다. 단 클래식의 손으로 쓴 `?` 화살표는 리뷰 전에도 보인다(해설이 이미 그 수를 말해 준다). |
| 명경기 | 자동 계산. 해설과 정확히 맞춰야 하는 수(주로 핵심 장면)는 JSON에 직접 지정해 덮어쓴다. |

범위 밖:

- 사용자가 직접 화살표를 그리는 기능. chessground의 우클릭 그리기는 지금 설정을 그대로 둔다.
- 엔진으로 위협을 계산하는 방식(null-move 탐색 등). 수마다 엔진을 돌려야 해서 무겁고, 리뷰가 도는 동안에는 쓸 수 없다.
- 30판 모든 수에 직접 지정하는 작업.

## 2. 시각 언어

| 표시 | chessground brush | 뜻 |
|---|---|---|
| 초록 화살표 | `green` | 이번 수가 노리는 것. 움직인 기물(또는 핀을 거는 기물)에서 목표로 그린다. 포크면 목표마다 한 개씩 그린다. |
| 빨간 원 | `red` | 위험한 기물. 공짜로 잡힐 기물, 핀에 묶인 기물. |
| 빨간 화살표 | `red` | 실수 뒤 상대가 노리는 응징 수. |
| 파란 화살표 | `blue` | 놓친 최선수. 실수·블런더·놓침 판정에서, 리뷰한 뒤에만 그린다. |

- 기존 힌트·엔진 라인 화살표(`paleBlue`)는 그대로 둔다.
- 놓친 수 화살표와 힌트 화살표가 같은 수면 힌트 쪽 하나만 그린다.
- 가이드는 한 수에 **최대 3개**까지만 그린다.
- 화살표는 시각 보조 장치다. 같은 내용을 코멘트·해설 문장이 이미 말하므로 따로 읽어 주는 텍스트는 두지 않는다.

## 3. 자동 계산: `src/engine/comment/guide.ts`

```ts
export type GuideKind = 'attack' | 'danger' | 'missed'
export interface GuideShape {
  kind: GuideKind
  /** 있으면 화살표, 없으면 to 칸에 원 */
  from?: Square
  to: Square
}
export function guideFor(input: CommentInput): GuideShape[]
```

- 입력은 코멘트와 같은 `CommentInput`이다. 리뷰 전이면 `positions`·`labels`가 비어 있고, 판 위 사실만 계산된다.
- `extractFacts`가 만든 사실을 도형으로 바꾼다. 문장과 화살표가 같은 사실에서 나오므로 서로 어긋나지 않는다.

| 사실 | 도형 |
|---|---|
| `mate` | 없음(메이트 수 자체로 충분하다) |
| `missed` | 직전 포지션 최선수 `from→to`, `missed` |
| `fork` | 움직인 기물 → 목표마다, `attack` |
| `pin` | 핀을 거는 기물 → 묶인 기물 `attack`, 묶인 기물 칸 `danger` |
| `threat`(새 사실) | 움직인 기물 → 목표, `attack` |
| `hanging` | 걸린 기물 칸, `danger` |
| `refutation` | 상대의 응징 수 `from→to`, `danger` 화살표(실수 뒤 상대가 무엇을 노리는지) |

- 우선순위: `missed` > `fork` > `pin` > `refutation` > `threat` > `hanging`. 앞에서부터 채우고 3개에서 자른다. 같은 칸·같은 화살표는 한 번만 넣는다.
- 사실 형식만 조금 넓힌다. 코멘트 문장 생성(`compose.ts`, `phrases.ko.ts`)은 바꾸지 않는다.
  - `fork`, `pin`에 목표 칸 목록(`targetSquares`, `pinnedFrom`처럼 필요한 칸)을 더한다.
  - `refutation`, `missed`에 UCI를 더한다.
- 새 사실 `threat`: 움직인 기물이 공격하는 상대 기물 중 **방어가 없거나 움직인 기물보다 비싼 것** 하나다(킹 제외, 체크는 `check` 사실이 맡는다). 여럿이면 가장 비싼 것을 고른다. 포크가 있으면 만들지 않는다. 코멘트 문장에는 쓰지 않고 가이드에만 쓴다.
- 칸 계산은 chess.js `attackers`만 쓴다. 사이에 기물이 끼어 막힌 줄은 공격으로 치지 않는다.

## 4. 명경기 직접 지정

`AnnotatedPly`에 선택 필드를 더한다.

```ts
export interface AnnotatedPly {
  ply: number
  text: string
  key?: boolean
  /** 보드 가이드. 있으면 자동 계산 대신 이것만 그린다. [] = 이 수는 가이드 없음 */
  guide?: string[]
}
```

짧은 표기:

| 표기 | 뜻 |
|---|---|
| `"d3h7"` | 초록 화살표(attack) |
| `"h7"` | 빨간 원(danger) |
| `"!d3h7"` | 빨간 화살표(danger) |
| `"?e2e4"` | 파란 화살표(missed) |

- 범위: 해설 문장이 특정 노림을 말하는 핵심 장면 위주로, 판마다 몇 개씩만 넣는다. 자동 가이드가 해설과 어긋나는 수는 `[]`로 끈다.
- 파서 `parseGuide(list): GuideShape[]`를 `src/sources/annotations.ts` 옆에 둔다.

### 검증(`validateAnnotations`에 추가)

- 표기가 위 형식인지, 칸 이름이 올바른지 확인한다.
- 화살표 출발 칸에 기물이 있는지 확인한다(그 수를 둔 뒤 포지션 기준). 단 `?` 화살표는 직전 포지션 기준이다.
- 초록·빨간 화살표는 출발 기물이 도착 칸을 실제로 공격하는지 chess.js `attackers`로 확인한다.
- 파란 화살표는 직전 포지션에서 둘 수 있는 수인지 확인한다.
- 3개를 넘으면 오류다.
- 퀴즈 장면 시작 포지션(`startPly`)의 가이드에 그 장면 첫 정답 수(`answerUci`)와 같은 화살표가 있으면 오류다.

## 5. 화면

- `ViewerPage`가 현재 수의 가이드를 고른다.
  - 그 수에 직접 지정한 가이드가 있으면 그것을 쓰고, 없으면 `guideFor`로 계산한다.
  - 계산 결과는 `useMemo`로 수마다 한 번만 만든다.
- 도형 변환은 `src/components/boardShapes.ts`에 `guideShape(g: GuideShape): DrawShape`로 더한다.
- `Board`의 `shapes`에는 가이드와 기존 힌트·라인 화살표를 합쳐 넘긴다.
- 토글:
  - 판정 카드에 "가이드" 토글 버튼(`aria-pressed`)을 둔다. 모바일 하단 막대에는 넣지 않는다(이미 버튼이 많다).
  - 기본값은 켜짐이다.
  - `src/app/boardPrefs.ts`와 같은 방식으로 `localStorage` 키 `chessling-guide`에 저장한다. 저장할 수 없으면 이번 세션에만 적용한다.
- 가이드를 그리지 않는 경우:
  - 퀴즈를 푸는 동안
  - 시작 포지션(ply 0)
  - 퀴즈 장면 시작 포지션의 자동 가이드는 `attack`만 남긴다. 놓친 수·반박 수(`missed`·`danger`)가 곧 퀴즈 정답일 수 있어서다.
  - 분기해 이어 두는 화면(`/play`)에는 적용하지 않는다.

## 6. 테스트

- `guide.test.ts`
  - 포크 → 화살표 2개, 핀 → 화살표 + 원, 노림(방어 없는 기물·더 비싼 기물), 걸린 기물 → 원
  - 리뷰 전에는 `missed`가 없고, 리뷰 뒤에는 놓친 수 화살표가 맨 앞에 온다
  - 사이에 기물이 끼어 막힌 줄은 노림으로 치지 않는다
  - 3개 제한과 중복 제거
- `parseGuide`·검증기 테스트: 잘못된 표기, 빈 칸 출발, 닿지 않는 화살표, 장면 정답 스포일러, 4개 이상
- `ViewerPage.test.tsx`: 토글을 끄면 보드에 가이드가 사라지고 새로 렌더해도 유지된다. 퀴즈 중에는 가이드가 없다.
- 명경기 데이터: 기존 `annotations.test.ts`가 30판 모두에 새 검증을 돌린다.
- E2E(`e2e/guide.spec.ts`): 오페라 게임 핵심 장면에서 `cg-container svg` 안에 화살표가 그려지고, 토글을 끄면 사라진다.

## 7. 작업 순서(계획에서 세분한다)

4. 화면: 도형 변환, 토글, 저장, 퀴즈·스포일러 처리
5. 명경기 핵심 장면 직접 지정(30판, 판마다 몇 개)
